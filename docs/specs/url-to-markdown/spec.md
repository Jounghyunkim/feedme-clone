# 웹 페이지 URL → Markdown → LLM 넘기기

웹 페이지 URL을 붙여넣으면 본문만 Markdown으로 추출해 보여 주고, 복사·다운로드하거나 프롬프트를 붙여 ChatGPT·Claude로 바로 넘기는 한 화면짜리 서비스.

## 연결된 자료

- [prototype.html](prototype.html) — 승인된 화면. 화면 구성, 요소 배치와 순서, 상태별 모습(빈 상태, 변환 중, 결과, 긴 본문 결과, 불러오기 실패, 본문 없음), 안내 문구, 좁은 화면 배치를 정한다. 이 명세와 다르면 명세의 동작이 우선하고, 화면 모습은 프로토타입을 따른다. 프로토타입 안의 본문과 도메인은 가짜 데이터다.
- [docs/decisions/ui-composition.md](../../decisions/ui-composition.md) — 버튼, 입력, 카드, 토글, 알림, 스켈레톤, 토스트 같은 일반 UI를 shadcn 구성과 semantic token으로 만드는 기준.
- [docs/decisions/brand-identity.md](../../decisions/brand-identity.md) — LG Active Red 기반 색상 token, 오류 색, LG CI 로고 파일과 헤더 배치(CI, 구분선, 서비스 이름).
- [docs/decisions/dependency-versions.md](../../decisions/dependency-versions.md) — 새 의존성(`defuddle`과 그것이 쓰는 DOM 라이브러리)을 추가할 때의 버전 기준.

## 사용자가 얻는 결과

- URL 하나만 붙여넣으면 광고·메뉴가 빠진 본문을 Markdown으로 받는다.
- 결과를 열기 전에 제목·저자로 맞는 페이지인지 확인하고, 렌더링된 본문을 읽어 볼 수 있다.
- 클릭 한 번으로 Markdown을 복사하거나 `.md` 파일로 저장한다.
- 클릭 한 번으로 ChatGPT나 Claude 새 탭을 열고, 고른 프롬프트와 본문이 입력창에 채워진 상태에서 시작한다. 본문이 너무 길면 클립보드 복사로 이어 가서 본문이 잘리지 않는다.
- 밝은 화면과 어두운 화면을 직접 고를 수 있다.

## 범위

1. **입력** — URL 입력칸과 변환 버튼. 입력칸에 내용이 있으면 지우기 버튼이 보이고, 누르면 입력과 결과·오류·프롬프트 선택이 모두 처음 상태로 돌아간다. Enter로도 변환한다.
2. **변환** — 입력한 페이지를 가져와 `defuddle` 라이브러리로 본문을 추출하고 Markdown으로 만든다.
3. **결과 확인** — 사이트 이름·도메인, 제목, 저자, 게시일, 분량을 담은 헤더와 렌더링된 Markdown 본문.
4. **내보내기**
   - 복사하기: Markdown을 클립보드에 넣는다.
   - `.md` 다운로드: 같은 Markdown을 파일로 저장한다.
   - ChatGPT로 열기 / Claude로 열기: 선택한 프롬프트를 본문 앞에 붙여 새 탭으로 넘긴다.
5. **프롬프트** — 없음 / 요약해줘 / 한국어로 번역해줘 / 쉽게 설명해줘 / 직접 입력. "직접 입력"을 고를 때만 텍스트 입력칸이 나타난다. 직접 입력한 문장은 한 번만 쓰고 어디에도 저장하지 않는다.
6. **다크 모드 토글** — 헤더의 아이콘 버튼으로 밝은 테마와 어두운 테마를 바꾼다.

## 수용 기준

입력과 변환
- 빈 입력이나 `http(s)://`로 시작하는 웹 주소가 아닌 값으로 변환하면 페이지를 가져오지 않고 입력칸 아래에 형식 오류 문구를 보여 준다. 입력을 고치기 시작하면 오류 표시가 사라진다.
- 변환을 누르면 결과가 올 때까지 변환 버튼이 "변환 중"으로 바뀌어 다시 누를 수 없고, 결과 자리에 스켈레톤이 보인다.
- 일반 글 페이지(예: `https://stephango.com/file-over-app`)를 변환하면 제목·저자·사이트가 헤더에 나오고 본문이 렌더링된 Markdown(제목, 목록, 인용, 코드 블록, 링크)으로 보인다.
- 저자 정보가 없는 페이지(예: `https://react.dev/learn`)는 저자 자리가 빈 칸이나 구분 기호 없이 생략된다. 게시일이 없을 때도 같다.
- 페이지를 가져오지 못하면(주소 없음, 4xx/5xx 응답, 연결 실패) "페이지를 불러오지 못했어요" 오류 알림을 보여 준다.
- 페이지는 가져왔지만 추출된 본문이 비어 있으면(예: `https://x.com`) "본문을 찾지 못했어요" 안내를 보여 주고 내보내기 동작은 보이지 않는다.
- 지우기 버튼을 누르면 입력칸이 비고, 결과·오류가 사라지고, 빈 상태 안내가 다시 보이고, 입력칸에 포커스가 간다.
- 다른 URL로 다시 변환하면 이전 결과가 새 결과로 바뀌고 프롬프트 선택은 "없음"으로 돌아간다.

내보내기
- 내보내는 Markdown은 첫 줄에 `# 제목`을 두고, 그 아래에 저자(있을 때)와 원문 URL을 적은 뒤 본문을 잇는다. 복사, 다운로드, LLM 넘기기 모두 이 같은 Markdown을 쓴다.
- 복사하기를 누르면 클립보드에 Markdown이 들어가고 "Markdown을 복사했어요" 토스트가 뜬다.
- `.md` 다운로드를 누르면 페이지 제목을 바탕으로 한 이름의 `.md` 파일이 저장된다. 파일 이름에 쓸 수 없는 문자는 제거되고, 제목이 없으면 도메인을 이름으로 쓴다.
- 프롬프트는 LLM으로 열 때만 붙는다. 복사와 다운로드에는 프롬프트가 들어가지 않는다.
- 프롬프트가 "없음"이 아니면 LLM에 넘기는 내용은 프롬프트 한 줄, 빈 줄, 내보내는 Markdown 순서다. "직접 입력"인데 칸이 비어 있으면 "없음"과 같이 동작한다.
- ChatGPT로 열기는 `https://chatgpt.com/`에, Claude로 열기는 `https://claude.ai/new`에 입력창 채우기 매개변수를 붙여 새 탭으로 연다. 이 서비스의 탭은 그대로 남는다.
- 넘길 내용 전체를 담은 주소가 길이 한도 안이면, 새 탭의 입력창에 프롬프트와 본문이 함께 채워지고 "새 탭에서 열었어요" 토스트가 뜬다.
- 길이 한도를 넘으면 넘길 내용 전체를 클립보드에 복사하고, 새 탭은 프롬프트만 채운 주소로 열고(프롬프트가 없으면 빈 새 대화), "본문이 길어서 클립보드에 복사했어요. 붙여넣기 하세요" 토스트를 평소보다 오래 띄운다. 본문을 잘라서 보내지 않는다.

프롬프트와 다크 모드
- 프롬프트는 한 번에 하나만 선택되고, 기본값은 "없음"이다.
- "직접 입력"을 고르면 입력칸이 나타나고 포커스가 가며, 다른 항목을 고르면 입력칸이 숨는다. 새로고침이나 새 변환 뒤에는 직접 입력한 문장이 남아 있지 않다.
- 다크 모드 토글을 누르면 화면 전체가 프로젝트의 dark token으로 바뀌고 아이콘이 달에서 해로 바뀐다. 새로고침해도 마지막 선택이 유지된다.

화면 공통
- 너비 390px 화면에서 가로 스크롤 없이 모든 동작을 쓸 수 있다. 복사·다운로드 버튼과 ChatGPT·Claude 버튼은 각각 두 칸으로 나란히 놓인다.
- 넓은 화면에서는 긴 본문을 스크롤하는 동안 내보내기 카드가 화면 위쪽에 붙어 있다.
- UI 문구는 한국어다.
- 헤더 왼쪽에 LG CI가 보이고, 다크 모드에서는 흰 글자 버전 CI로 바뀐다.

## 확정된 제약과 이유

- **본문 추출은 `defuddle` npm 라이브러리로 한다.** 사용자가 정한 조건이다. `defuddle.md` 호스팅 API는 쓰지 않는다. 라이브러리로 충분하고, API는 요청 수가 늘면 유료 키가 필요하다.
- **페이지 가져오기와 추출은 브라우저가 아닌 서버 쪽에서 한다.** 브라우저에서 다른 사이트의 HTML을 직접 받으면 CORS로 막힌다. `defuddle`은 Node용 진입점(`defuddle/node`)과 DOM 구현(linkedom, JSDOM, happy-dom 중 하나)으로 서버에서 동작한다.
- **본문이 주소에 들어가면 링크로, 넘치면 클립보드 복사로 넘긴다.** 사용자가 2026-11-18에 정했다. 링크 한 번으로 끝나는 경험을 대부분의 글에 주면서, 긴 글이 잘린 채 LLM에 들어가는 일을 막는다. "항상 복사"는 짧은 글도 매번 붙여넣게 하고, "잘라서 보내기"는 긴 글의 뒷부분을 잃게 해서 택하지 않았다.

## 가정 (바꿔도 되는 기본값)

- **길이 한도:** 넘길 주소의 전체 길이(인코딩 후)가 30,000자 이하면 링크로 보낸다. 2026-11-18 측정에서 ChatGPT는 인코딩 기준 32,000자 쿼리는 받았고 64,000자는 431로 거부했다. Claude는 봇 차단(403) 때문에 128,000자에서 414가 나온 것 말고는 측정하지 못해 같은 한도를 쓴다.
- **다크 모드 초기값:** 저장된 선택이 없으면 운영체제 설정을 따른다. 선택은 이 브라우저에만 저장한다.
- **서비스 이름:** 헤더에서 LG CI 오른쪽에 붙는 서비스 이름은 "Feedme"다(저장소 이름에서 가져옴).
- **분량 표시:** 헤더의 분량은 `defuddle`이 주는 단어 수로 "약 N단어"라고 표시한다.
- **게시일 표시:** 날짜만 한국어 형식(예: 2026년 10월 2일)으로 보여 준다.

## 범위 밖

- 변환 기록, 즐겨찾기, 직접 입력 프롬프트의 저장. 사용자가 직접 입력은 1회용이라고 정했고, 나머지는 요청 범위에 없다.
- 로그인, 계정, 사용량 제한.
- 로그인이 필요한 페이지나 브라우저 스크립트로 본문을 그리는 페이지의 추출. "본문 없음" 안내로 끝낸다.
- 결과 Markdown 편집, 원본(raw) Markdown 보기 전환.
- ChatGPT·Claude 외 다른 LLM 서비스.
- 스펙에 없는 보안 하드닝(예: 내부망 주소 차단), 성능 방어. 이 저장소의 검증·리뷰 예산(`AGENTS.md`)에 따라 범위 밖이다.

## 남은 위험

- **Claude 입력창 채우기 동작:** `https://claude.ai/new?q=`로 입력창이 실제로 채워지는지 로그인한 상태에서 확인하지 못했다. 동작하지 않으면 Claude로 열기는 빈 새 대화가 될 수 있다. 구현 후 실제 브라우저에서 로그인한 계정으로 확인해야 한다. 안 되면 Claude 쪽은 항상 클립보드 복사 경로로 보내는 방식을 검토한다.
- **ChatGPT 매개변수 동작:** `?q=`는 공식 문서화된 기능이 아니라서 예고 없이 바뀔 수 있다. 바뀌면 두 서비스 모두 클립보드 경로로만 넘기도록 바꿔야 한다.
- **길이 한도의 정확도:** 실제로 거부되는 경계는 30,000~64,000자 사이 어딘가로만 확인됐다. 한도를 낮게 잡아서 링크로 보낼 수 있는 글 일부가 클립보드 경로로 갈 수 있다.
- **추출 품질:** `defuddle` 0.19.6은 블로그 글과 문서 페이지는 잘 추출했지만, 사이트에 따라 본문 일부가 빠지거나 메뉴가 섞일 수 있다. 이 서비스는 결과를 그대로 보여 주고 손보지 않는다.
- **클립보드 권한:** 브라우저가 클립보드 쓰기를 거부하면 복사와 긴 본문 넘기기가 실패한다. 이때는 실패 토스트로 알리고 `.md` 다운로드를 권한다.

## 확인한 근거

- `defuddle` 0.19.6 + `linkedom` 0.18.15를 임시 폴더에서 설치해 실제 페이지로 확인했다(2026-11-18).
  - `stephango.com/file-over-app`: 제목·저자·게시일 모두 나옴, Markdown 약 2,200자.
  - `react.dev/learn`: 저자 빈 값, Markdown 약 15,700자(인코딩 약 24,300자).
  - `ko.wikipedia.org/wiki/마크다운`: Markdown 약 30,200자(인코딩 약 79,600자) → 링크 한도를 넘는 예.
  - `x.com`: 제목은 나오지만 본문 0자 → "본문 없음" 예.
- `defuddle` 문서(https://defuddle.md/docs): Node에서는 `defuddle/node`의 `Defuddle(document, url, { markdown: true })`를 쓰고, 결과에 `title`, `author`, `site`, `domain`, `favicon`, `published`, `wordCount`, `content`가 들어간다. `defuddle/node`를 쓰려면 ESM 환경이 필요하다고 적혀 있다.
- 다시 검토할 조건: `defuddle`이 메이저 버전을 올려 결과 형태가 바뀌거나, ChatGPT·Claude가 입력창 채우기 매개변수를 바꾸면 위 결정과 한도를 다시 본다.
