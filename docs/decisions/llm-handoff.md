# LLM으로 넘기기

## Decisions

- 변환한 Markdown은 ChatGPT(`https://chatgpt.com/?q=`)와 Claude(`https://claude.ai/new?q=`)의 입력창 채우기 매개변수에 담아 새 탭으로 넘긴다.
- 넘길 주소 전체 길이(인코딩 후)가 30,000자 이하면 프롬프트와 본문을 모두 주소에 담는다. 넘으면 프롬프트와 본문 전체를 클립보드에 복사하고, 새 탭은 프롬프트만 담은 주소로 연다. 프롬프트가 없으면 빈 새 대화를 연다. 본문을 잘라서 보내지 않는다.
- 넘기는 내용은 프롬프트 한 줄, 빈 줄, 내보내는 Markdown 순서다. 프롬프트가 없으면 Markdown만 보낸다.
- 내보내는 Markdown은 `# 제목`, 저자(있을 때), 원문 URL, 본문 순서다. 복사, `.md` 다운로드, LLM 넘기기가 모두 같은 Markdown을 쓴다.
- 프롬프트는 LLM으로 넘길 때만 붙는다. 복사와 다운로드에는 들어가지 않는다.
- 직접 입력한 프롬프트는 한 번만 쓰고 저장하지 않는다.

## Boundaries

- ChatGPT와 Claude 외의 LLM 서비스는 다루지 않는다.
- 30,000자는 측정에 근거한 보수적인 값이다. 실제 거부 경계는 32,000자와 64,000자 사이로만 확인됐다.

## Why

사용자가 링크 한 번으로 끝나는 경험을 대부분의 글에 주되, 긴 글이 잘린 채 LLM에 들어가는 일은 막기로 정했다. 주소에는 길이 한도가 있어서 긴 글은 주소로 넘길 수 없다. 클립보드로 대신 넘기면 사용자가 한 번 붙여넣어야 하지만 본문은 온전히 전달된다.

프롬프트를 복사와 다운로드에 넣지 않는 이유는, 그 결과물이 LLM이 아닌 곳에서도 쓰이는 원문 사본이기 때문이다.

## Reconsider when

- 로그인한 Claude에서 `?q=`가 입력창을 채우지 않는다는 것이 확인되면, Claude는 길이와 관계없이 클립보드 경로로 넘긴다. 이 동작은 아직 확인하지 못했다.
- ChatGPT의 `?q=`는 공식 문서화된 기능이 아니다. 동작이 바뀌면 두 서비스 모두 클립보드 경로로만 넘긴다.
- 두 서비스의 주소 길이 한도를 다시 측정해 30,000자보다 확실히 크다는 근거가 생기면 한도를 올린다.

## Still-rejected alternatives

- 길이와 관계없이 항상 클립보드로 복사하고 여는 방식: 짧은 글도 매번 붙여넣어야 한다.
- 한도를 넘는 본문을 잘라서 주소에 담는 방식: 긴 글의 뒷부분이 사용자 모르게 빠진 채 LLM에 들어간다.

## Evidence worth preserving

- 2026-11-18 측정. `?q=` 뒤에 인코딩된 문자를 붙여 요청했다.
  - ChatGPT는 2,000–32,000자에서 200, 64,000자에서 431, 128,000자에서 414를 돌려줬다.
  - Claude는 봇 차단 때문에 128,000자 미만에서 모두 403이었고, 128,000자에서 414였다.
- 문서 길이 예시. 한국어 위키백과 「마크다운」 문서는 Markdown 약 30,300자로, 인코딩하면 약 79,900자가 되어 한도를 넘는다. 반면 `react.dev/learn`은 인코딩 후 약 24,300자로 한도 안에 든다.
